# 예시를 보여 주는 퓨샷 기법

## 설명보다 예시가 빠를 때

원하는 형식을 말로 설명하기 어려울 때는 예시를 한두 개 보여 주는 것이 빠릅니다. 예시 없이 묻는 것을 제로샷(Zero-Shot), 예시를 한 개 주면 원샷(One-Shot), 여러 개 주면 퓨샷(Few-Shot)이라고 부릅니다.

```prompt 퓨샷: 국가시험형 문제 만들기
다음 예시와 같은 형식과 난이도로 [주제] 문제 3개를 만들어 주세요.

예시
문제: 뇌졸중 후 경직이 있는 위팔의 굽힘 공동운동 패턴에 맞서는 자세 조절로 옳은 것은?
보기: ① 어깨 안쪽돌림 유지 ② 어깨 벌림·가쪽돌림, 팔꿈치 폄 ③ 아래팔 엎침 유지 ④ 손가락 굽힘 유지 ⑤ 어깨뼈 뒤당김 유지
정답: ②
해설: 굽힘 공동운동과 반대 방향으로 자세를 잡아 경직을 조절한다.

조건: 보기 5개, 정답 1개, 해설 2문장 이내, 교재 용어 사용
```

## 예시를 고를 때 주의할 점

- **예시는 정확해야 합니다.** 틀린 예시를 주면 AI도 그 틀린 방식을 따라 합니다.
- **예시가 너무 비슷하면 결과도 비슷해집니다.** 형식은 같고 내용은 다른 예시를 고릅니다.
- **예시의 내용을 복사하는 경우가 있습니다.** "예시의 주제는 쓰지 말 것"을 덧붙입니다.
- **시험 문제를 예시로 쓸 때** 공개된 기출문제의 문장을 그대로 옮겨 자료를 만들거나 배포하지 않습니다. 형식만 참고합니다.

## 내 글투를 예시로 주기

과제 문장을 다듬을 때 내가 쓴 좋은 문단을 예시로 주면, AI가 내 말투를 유지하며 다듬어 줍니다. 처음부터 AI 문장으로 바뀌는 것을 막을 수 있습니다.

# 단계적으로 따지게 하기

## 판단 과정을 드러내게 합니다

사례 문제나 계산 문제는 AI가 바로 답만 내면 어디서 틀렸는지 알 수 없습니다. 단계별로 따지라고 하면 판단 과정이 드러나 확인하기 쉬워집니다. 이 방법을 단계적 사고(Chain of Thought)라고 부르기도 합니다. 최근 모델은 스스로 여러 단계를 거쳐 추론하는 기능을 갖춘 경우가 많지만, 내가 확인할 수 있도록 단계를 글로 보여 달라고 요청하는 것은 여전히 유용합니다.

```prompt 단계적 사례 판단
아래 가상 사례를 단계별로 판단해 주세요.
[가상 사례: 예, 70대 남성, 3일 전부터 식사량 감소, 오늘 아침 혼돈, 체온 38.2°C, 소변이 탁함]

1단계: 사례에서 중요한 정보를 모두 나열
2단계: 가능한 원인이나 문제를 2~3개 제시하고 각각의 근거
3단계: 추가로 확인해야 할 정보
4단계: [직종] 학생이 할 수 있는 우선 행동과 보고할 대상
각 단계에서 확실하지 않은 부분은 표시해 주세요. 이 답은 학습용이며 실제 환자 판단에 쓰지 않습니다.
```

## 단계를 내가 먼저 써 보기

더 좋은 공부법은 내가 먼저 단계를 써 보고 AI의 단계와 비교하는 것입니다. 내가 빠뜨린 단계, AI가 틀린 단계를 찾는 과정에서 임상 추론 능력이 자랍니다.

## 자기 점검시키기

AI가 낸 답을 다시 검토하게 하면 실수를 일부 줄일 수 있습니다.

```prompt 자기 점검
방금 답한 내용을 다시 검토해 주세요.
1. 계산이나 사실 가운데 틀릴 수 있는 부분
2. 질문의 조건을 빠뜨린 부분
3. 확신이 낮은 부분과 확인할 자료
를 찾아 표로 정리해 주세요.
```

자기 점검도 완벽하지는 않습니다. 마지막 확인은 교재와 공식 자료로 합니다.

# 채용공고 기반 모의면접

## 공고에서 역량 뽑기

```prompt 채용공고 역량 분석
아래는 제가 지원하려는 기관의 채용공고와 인재상입니다.
[붙여 넣기]

1. 중요하게 보는 역량 5개와 근거 문장
2. 역량별로 면접에서 나올 만한 질문 2개
3. 역량별로 제가 준비할 경험의 종류
를 표로 정리해 주세요.
```

## 퓨샷으로 모의면접관 만들기

모의면접관에게 좋은 꼬리 질문의 예를 보여 주면 질문 수준이 올라갑니다.

```prompt 모의면접관 설계
당신은 [기관 종류]의 [직종] 채용 면접관입니다. 위에서 정리한 역량을 확인하는 면접을 진행해 주세요.

좋은 꼬리 질문의 예
지원자: 실습 중 환자 안전을 위해 노력했습니다.
면접관: 구체적으로 어떤 상황에서 무엇을 확인했나요? 그때 확인하지 않았다면 어떤 일이 생길 수 있었나요?

진행 방식
- 한 번에 한 질문, 제 답에 따라 꼬리 질문 1개
- 역량 5개를 모두 다룰 때까지 진행
- 끝나면 역량별로 제 답이 보여 준 것과 부족한 것을 표로 정리
- 제 답에 직무 지식 오류가 있으면 지적
```

## 연습 기록하기

| 질문 | 내 답 요약 | 받은 피드백 | 고친 답 |
|---|---|---|---|
| | | | |

같은 질문에 세 번 답해 보고, 답이 어떻게 나아졌는지 비교합니다. 답을 외우지 말고 경험과 구조를 익힙니다.

## 도우미 지시문 쓰기

ChatGPT의 GPTs, Gemini의 Gems, Claude의 프로젝트처럼 지시문과 자료를 저장해 두는 기능을 쓰면 매번 프롬프트를 다시 넣지 않아도 됩니다. 기능 이름과 사용 조건은 서비스마다 다르므로 확인합니다.

```prompt 학습 도우미 지시문 만들기
아래는 제가 4주 동안 만든 프롬프트와 결과가 좋았던 예입니다.
[1~4주 재료 붙여 넣기]

이 재료로 [과목] 학습 도우미의 지시문을 만들어 주세요.
1. 역할과 대상
2. 도우미가 하는 일 3~4가지(개념 설명, 요약, 문제 출제, 오답 설명 등)와 각각의 답 형식
3. 하지 않을 일(추측으로 수치 쓰기, 과제 대필, 환자 판단)
4. 질문에 틀린 전제가 있으면 먼저 바로잡기
5. 확실하지 않으면 교재 확인을 권하기
800자 이내로 써 주세요.
```

## 도우미 시험하기

!!! 도우미를 쓰기 전에 시험합니다
- 범위 안의 개념 질문에 형식대로 답하는가
- 틀린 전제를 넣은 질문을 바로잡는가
- 범위 밖 질문에 모른다고 하거나 범위를 알려 주는가
- 과제를 대신 써 달라는 요청을 거절하고 도와줄 방법을 제안하는가
- 수치를 물으면 출처 확인을 권하는가

# 4주차 자주 묻는 질문

**단계적으로 따지라고 하면 답이 너무 길어집니다.**
"단계는 한 줄씩, 전체 10줄 이내"처럼 분량을 정합니다.

**도우미를 만들었는데 가끔 지시를 어깁니다.**
지시문의 가장 중요한 규칙을 맨 앞에 두고, 어긴 사례를 예로 들어 "이런 경우에는 이렇게 하세요"를 더합니다. 그래도 완벽하지 않으므로 결과 확인은 계속합니다.
