# 과업지시서와 제안요청서

## 두 문서의 차이

외부 업체에 일을 맡길 때는 무엇을 원하는지 문서로 정확히 알려야 합니다. 이 문서가 모호하면 업체마다 다른 것을 제안하고, 계약 뒤에도 "이것까지 해야 하느냐"는 다툼이 생깁니다.

| 구분 | 과업지시서(과업내용서) | 제안요청서(RFP) |
|---|---|---|
| 목적 | 수행할 일의 범위와 기준을 정함 | 업체에게 수행 방법을 제안하도록 요청함 |
| 쓰임 | 수의계약, 단순 용역, 계약서 첨부 | 협상에 의한 계약, 제안 평가가 필요한 사업 |
| 핵심 내용 | 과업 범위, 산출물, 일정, 품질 기준 | 사업 개요, 요구사항, 제안서 작성 방법, 평가 기준 |
| 업체의 자율 | 적음 | 많음(방법은 업체가 제안) |

두 문서 모두 학교의 계약 관련 규정과 국가계약법령 등 관련 법령의 적용을 받습니다. 계약 방법, 공고 기간, 평가 방식은 계약 담당 부서와 먼저 협의합니다. AI는 문서의 구조와 문장을 만드는 데 쓰고, 계약 방법과 법적 요건 판단은 맡기지 않습니다.

## 좋은 요구사항의 조건

요구사항은 문서의 핵심입니다. 좋은 요구사항은 다음 조건을 갖춥니다.

| 조건 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 측정 가능 | 빠른 응답 속도 | 동시 접속 200명 기준 화면 응답 3초 이내 |
| 하나의 내용 | 회원 관리와 통계 기능 제공 | 요구사항을 회원 관리, 통계로 나눔 |
| 검수 가능 | 사용자 친화적 화면 | 주요 화면 시안 2종 제출, 발주처 승인 후 개발 |
| 범위 명확 | 유지보수 지원 | 하자보수 기간 12개월, 장애 접수 후 24시간 이내 조치 착수 |
| 특정 업체 배제 금지 | 특정 제품명 지정 | 필요한 성능과 규격으로 기술 |

> 특정 제품이나 업체를 지정하는 표현은 공정한 경쟁을 막아 문제가 될 수 있습니다. 성능, 규격, 호환성 기준으로 씁니다. 위 표의 수치는 표현 방식을 보여 주는 예시이며 실제 기준은 사업에 맞게 정합니다.

# 과업지시서 만들기

## 표준 목차

1. 과업 개요: 과업명, 목적, 기간, 장소
2. 과업 범위: 수행할 일의 목록
3. 세부 과업 내용: 항목별 내용과 기준
4. 산출물: 제출할 결과물, 형식, 시기
5. 수행 일정: 단계별 일정과 보고
6. 인력과 수행 체계: 필요한 인력 자격과 수
7. 품질과 안전 관리
8. 검수 기준과 방법
9. 보안과 개인정보 보호
10. 기타 사항: 저작권, 하자 보수, 변경 절차

## 프롬프트

```prompt 프롬프트 1. 과업지시서 초안
역할: 당신은 대학 용역 계약 문서 작성을 돕는 행정 담당자입니다.

아래 메모로 과업지시서 초안을 작성해 주세요.
- 과업명: [예: 2026학년도 신입생 오리엔테이션 행사 대행]
- 목적: [ ]
- 기간·장소·규모: [ ]
- 수행할 일: [메모 형태로 나열]
- 산출물: [ ]
- 예산 규모: [총액만, 또는 비워 둠]

작업:
1. 위 표준 목차 10개 항목으로 작성합니다.
2. 세부 과업 내용은 표(과업 항목, 내용, 기준, 산출물)로 씁니다.
3. 요구사항은 측정 가능하고 검수할 수 있는 문장으로 씁니다.
4. 제가 주지 않은 수치 기준은 [기준 설정 필요]로 남깁니다.

지킬 것: 특정 업체나 제품명을 쓰지 않습니다. 계약 방법이나 법령 조항은 쓰지 말고 [계약 담당 부서 확인]으로 표시합니다.
```

## 과업 유형별 점검 항목

| 유형 | 빠뜨리기 쉬운 항목 |
|---|---|
| 행사 대행 | 우천 등 비상 계획, 안전 요원, 보험, 참가자 개인정보 처리, 사진 저작권 |
| 정보시스템 구축 | 학교 통합인증 연동, 개인정보 암호화, 소스코드 제출, 웹 접근성, 하자 보수 |
| 기자재 구매 | 설치 장소 여건(전기, 공간), 교육 제공, 소모품 공급, 무상 보증 기간 |
| 연구·조사 용역 | 원자료 제출, 연구윤리, 결과 활용 권리 |
| 영상·홍보물 제작 | 초상권 동의, 음원 저작권, 수정 횟수, 원본 파일 제출 |

```prompt 프롬프트 2. 빠진 항목 점검
아래 과업지시서 초안을 검토해 주세요.
[초안]

이 과업이 [유형]이라는 점을 고려해 빠진 항목, 모호해서 분쟁이 생길 수 있는 문장, 검수 기준이 없는 요구사항을 표로 정리해 주세요. 표 열: 위치, 문제, 수정 제안.
```

# 제안요청서 만들기

## 제안요청서 구성

1. 사업 개요: 배경, 목적, 범위, 기간, 예산
2. 현황: 현재 시스템이나 운영 방식, 문제점
3. 요구사항: 기능, 성능, 보안, 품질, 프로젝트 관리, 지원 요구사항
4. 제안서 작성 안내: 목차, 분량, 제출 방법
5. 평가 방법: 평가 항목과 배점(계약 담당 부서 기준에 따름)
6. 기타: 비밀 유지, 제안서 반환, 질의 응답 일정

## 요구사항 목록 만들기

정보시스템 제안요청서에서는 요구사항마다 고유 번호를 붙여 목록으로 관리하는 방식이 널리 쓰입니다. 번호가 있으면 제안서 평가, 계약, 검수 단계에서 같은 기준으로 확인할 수 있습니다.

```prompt 프롬프트 3. 요구사항 목록
[사업명] 제안요청서의 요구사항 목록을 만들어 주세요.

현재 상황과 원하는 것:
[메모: 지금의 문제, 필요한 기능, 사용자 수, 연동할 학교 시스템, 보안 요건]

형식: 표(요구사항 번호, 분류, 요구사항 명칭, 상세 내용, 검수 방법).
분류는 기능(SFR), 성능(PER), 보안(SER), 품질(QUR), 프로젝트 관리(PMR), 지원(PSR)으로 나눕니다.
상세 내용은 측정 가능하게 쓰고, 제가 주지 않은 수치 기준은 [기준 설정 필요]로 남겨 주세요.
```

## 사업 규모에 맞추기

작은 사업에 큰 사업의 제안요청서 형식을 그대로 쓰면 업체가 참여를 꺼립니다. 반대로 큰 사업을 간단한 문서로 발주하면 계약 뒤 분쟁이 생깁니다. AI에게 "이 사업의 예산 규모와 기간에 비해 요구사항이 과하거나 부족한 부분을 알려 주세요"라고 물어 균형을 점검합니다.

# 외부 기관 공문과 서한

## 대외 공문의 원칙

외부 기관에 보내는 공문은 학교를 대표합니다. 내부 기안문과 달리 상대 기관의 입장에서 무엇을 요청받는지 분명해야 합니다.

- **첫 문장에 목적:** 무엇을 요청하는지 바로 씁니다.
- **상대의 부담을 줄이는 정보:** 일정, 소요 시간, 필요한 협조 범위를 구체적으로 적습니다.
- **회신 방법과 기한:** 언제까지, 어떤 방법으로 회신하면 되는지 적습니다.
- **담당자 연락처:** 문의할 사람을 분명히 적습니다.

## 유형별 프롬프트

```prompt 프롬프트 4. 대외 협조 공문
[수신 기관]에 보낼 협조 요청 공문을 작성해 주세요.

내용:
- 요청 목적: [예: 재학생 현장실습 기관 협약 체결 협의]
- 요청 사항: [구체적으로]
- 일정: [ ]
- 우리가 제공하는 것: [예: 실습 지도교수 배치, 실습생 보험 가입]
- 회신 기한과 방법: [ ]

형식: 대외 공문 본문(관련, 본문, 붙임). 정중하고 간결한 공문체. 상대 기관이 판단에 필요한 정보가 빠지지 않게 써 주세요.
```

```prompt 프롬프트 5. 초청 서한
[행사명]에 [초청 대상, 예: 지역 보건소장]을 초청하는 서한을 작성해 주세요.

포함할 내용: 행사 취지, 일시·장소, 초청 대상이 맡을 역할(축사, 패널 등)과 소요 시간, 참석 회신 방법과 기한, 주차·안내 정보 자리 [ ].
분량: A4 한 쪽 이내. 격식 있는 서한체이되 과도한 미사여구는 쓰지 않습니다.
```

## 의료기관·산업체와의 서한

의료기관에 보내는 문서는 진료 일정상 회신이 늦을 수 있으므로 기한을 넉넉히 잡고, 담당 부서(교육수련부, 간호부, 재활의학과 등)를 정확히 지정합니다. 산업체에 보내는 협약 제안 서한에는 학교와 협력했을 때 산업체가 얻는 이점(인력 양성, 공동 연구, 시설 활용)을 구체적으로 씁니다.

# 검증

## 계약 문서에서 특히 확인할 것

| 항목 | 확인 |
|---|---|
| 계약 방법과 공고 | 계약 담당 부서와 관련 법령 기준 확인 |
| 특정 업체 지정 | 제품명, 상표, 특정 업체만 가능한 조건이 없는지 |
| 수치 기준 | 실제 필요에 맞는지, 근거가 있는지 |
| 개인정보와 보안 | 업체가 다루는 개인정보 범위, 위탁 계약 조항 |
| 저작권과 산출물 권리 | 결과물의 권리 귀속 |
| 예산 | 예산 총액과 과업 범위의 균형 |

!!! 공고·발송 전에 확인합니다
- 계약 방법과 법적 요건을 계약 담당 부서와 확인했다
- 특정 업체나 제품을 지정하는 표현이 없다
- 요구사항마다 검수 방법이 있다
- [기준 설정 필요] 표시가 모두 채워졌다
- 개인정보 처리와 보안 요구사항이 들어갔다
- 대외 공문의 수신 기관명과 부서명이 정확하다
- 회신 기한이 상대 기관이 대응할 수 있는 기간이다
- AI에 공개 전 예산 세부 내역이나 내부 평가 정보를 넣지 않았다

# 바이탈에서 이어서 하기

- **보도자료·공지·회의록·결과보고서 작성 앱:** 협약식이나 행사 뒤 보도자료와 결과보고서를 만듭니다.
- **산학협력단 결의서 스마트 검증기:** 용역 대금 집행 시 견적서, 거래명세서, 결의서의 금액과 날짜를 대조합니다.
- **프롬프트 라이브러리 3-8, 3-9:** 정중한 회신 메일과 예산 산출 근거 프롬프트를 입력칸 방식으로 씁니다.
