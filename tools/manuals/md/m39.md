# 회의록이 하는 일

## 좋은 회의록의 조건

회의록은 회의에서 무엇이 결정되었고 누가 무엇을 언제까지 하기로 했는지 남기는 문서입니다. 발언을 빠짐없이 옮긴 기록이 좋은 회의록은 아닙니다. 회의에 참석하지 않은 사람이 읽고 결과를 바로 이해할 수 있고, 다음 회의에서 실행 여부를 확인할 수 있어야 합니다.

| 좋은 회의록 | 나쁜 회의록 |
|---|---|
| 결정 사항이 문장으로 분명함 | "논의함"으로 끝나 결론을 알 수 없음 |
| 실행 과제마다 담당과 기한이 있음 | "추후 검토"만 있음 |
| 안건별로 구조가 같음 | 발언 순서대로 나열 |
| 쟁점과 반대 의견을 간결히 남김 | 다수 의견만 남기거나 모든 발언을 옮김 |
| 회의 직후 하루 이틀 안에 공유 | 일주일 뒤에 공유 |

## 회의록의 종류

| 종류 | 쓰임 | 상세도 |
|---|---|---|
| 의결 기구 회의록 | 규정에 따른 위원회 | 안건, 의결 정족수, 의결 결과를 규정에 맞게 기록 |
| 업무 협의 회의록 | 부서 간 협의 | 결정과 실행 과제 중심 |
| 산학협력 회의록 | 외부 기관과의 협의 | 합의 사항과 양측 담당을 명확히 |
| 간단 메모 | 팀 내부 회의 | 할 일 목록 수준 |

의결 기구 회의록은 학교 규정이 정한 기재 사항(개의 시각, 출석 위원, 의결 결과 등)이 있으므로 해당 규정을 먼저 확인합니다.

# 녹음과 녹취

## 녹음 전 확인

- **참석자 동의:** 회의 시작 때 녹음 사실과 목적(회의록 작성), 보관 기간을 알리고 동의를 받습니다.
- **외부 참석자:** 외부 기관 참석자가 있으면 특히 분명히 동의를 받습니다.
- **비공개 안건:** 인사, 징계처럼 민감한 안건은 녹음하지 않거나 해당 부분을 멈춥니다.

## 음성 기록 도구 사용

클로바노트처럼 음성을 글로 바꾸는 도구는 발언자를 구분하고 시간을 표시해 줍니다. 몇 가지를 지키면 정확도가 높아집니다.

- 녹음 기기를 회의 탁자 가운데 둡니다.
- 발언자가 겹치지 않게 진행합니다.
- 회의 시작 때 참석자가 소속과 이름을 한 번씩 말하면 발언자 구분이 쉬워집니다.
- 전문 용어와 기관명은 도구의 사용자 사전 기능에 미리 등록합니다.

## 녹취록 정리 전 처리

녹취록을 생성형 AI에 넣기 전에 다음을 처리합니다.

1. 참석자 이름을 직위나 역할로 바꿉니다(예: 김OO 팀장 → 학사팀장).
2. 민감한 발언(개인 평가, 인사 관련 언급)을 지웁니다.
3. 회의와 무관한 잡담 구간을 지웁니다.

# 회의록 만들기

## 기본 프롬프트

```prompt 프롬프트 1. 공식 회의록 정리
역할: 당신은 대학 위원회 간사입니다.

아래 녹취록(참석자는 역할로 표기)을 공식 회의록으로 정리해 주세요.
[녹취록]

구성:
1. 회의 개요: 회의명, 일시, 장소, 참석자(역할), 안건 목록
2. 안건별 정리(안건마다 같은 구조)
   - 논의 요약: 핵심 의견 3~5개, 발언자 역할 표시
   - 쟁점: 의견이 갈린 부분과 각 입장 한 줄씩
   - 결정 사항: 합의된 결론을 문장으로
3. 실행 과제 표: 번호, 과제, 담당, 기한, 관련 안건
4. 다음 회의 안건과 예정일

지킬 것:
- 녹취록에 없는 결정, 담당, 기한을 만들지 않습니다. 없으면 [미정].
- "검토하기로 함", "다시 논의함"은 결정 사항이 아니라 실행 과제나 다음 회의 안건으로 둡니다.
- 구어체와 중복 발언은 정리하되 발언의 뜻을 바꾸지 않습니다.
- 문체는 개조식, 명사형 종결.
```

## 결정과 할 일을 구분하는 기준

AI가 가장 자주 헷갈리는 부분은 결정과 할 일의 구분입니다.

| 녹취 표현 | 분류 | 이유 |
|---|---|---|
| "그럼 3월 둘째 주로 확정하죠" | 결정 | 결론이 났음 |
| "예산은 학과에서 다시 뽑아 보시고요" | 실행 과제 | 누군가 해야 할 일 |
| "그건 다음에 다시 얘기하죠" | 다음 회의 안건 | 결론 보류 |
| "이런 방향이 좋을 것 같습니다" | 논의 요약 | 한 사람의 의견 |
| "반대 의견 없으시면 원안대로 하겠습니다" + 반대 없음 | 결정 | 합의 확인 |

회의록 초안을 받은 뒤 "결정 사항 가운데 녹취록에서 합의를 확인한 발언이 없는 항목을 표시해 주세요"라고 다시 물으면 잘못 분류된 항목을 찾기 쉽습니다.

## 메모만 있을 때

녹음하지 않은 회의는 메모를 바탕으로 정리합니다. 메모가 짧으면 AI가 빈 부분을 일반론으로 채우기 쉬우므로 "메모에 있는 내용만 쓰고, 빈 부분은 [확인 필요]로 남겨 주세요"를 꼭 덧붙입니다.

# 실행 과제 관리

## 실행 과제를 잘 쓰는 법

실행 과제는 다음 회의에서 "했는가, 안 했는가"를 확인할 수 있게 써야 합니다.

| 모호한 과제 | 확인 가능한 과제 |
|---|---|
| 홍보 방안 검토 | 신입생 대상 홍보 카드뉴스 3종 초안 작성 |
| 예산 확인 | 2027년 행사 예산 소요액 산출표 작성 후 기획처 제출 |
| 관련 부서 협의 | 학생처와 행사 일정 협의 후 결과를 위원회 메일로 공유 |

```prompt 프롬프트 2. 실행 과제 다듬기
아래 실행 과제 목록을 다음 회의에서 완료 여부를 확인할 수 있는 문장으로 고쳐 주세요.
[실행 과제 목록]

과제마다 "무엇을, 어떤 결과물로, 누구에게"가 드러나게 하고, 원래 뜻을 넘어서는 내용은 추가하지 마세요. 담당과 기한은 원래 값을 그대로 둡니다.
```

## 역산 일정표

행사나 사업처럼 마감일이 정해진 일은 마감일에서 거꾸로 일정을 잡습니다. 이를 작업분해구조(WBS)와 역산 일정이라고 합니다.

```prompt 프롬프트 3. 역산 일정표
[행사명]을 [날짜]에 열기로 결정했습니다. 회의에서 정한 실행 과제는 다음과 같습니다.
[실행 과제 목록]

1. 실행 과제를 세부 작업으로 나누고, 작업 사이의 선후 관계를 표시해 주세요.
2. 행사일에서 거꾸로 계산해 작업별 시작일과 완료일을 정한 일정표를 만들어 주세요.
3. 결재, 외부 기관 회신처럼 우리가 통제할 수 없는 기간에는 여유 기간을 두고 표시해 주세요.

표 열: 작업, 담당, 시작일, 완료일, 선행 작업, 비고.
날짜에는 요일을 함께 적고, 주말에 마감이 걸리면 표시해 주세요.
```

> AI는 날짜와 요일 계산을 자주 틀립니다. 일정표의 날짜는 달력으로 다시 확인합니다.

## 다음 회의에서 점검

다음 회의 시작 때 지난 회의 실행 과제의 진행 상태를 먼저 확인합니다. 지난 회의록의 실행 과제 표에 상태 열(완료, 진행 중, 지연)을 더해 회의 자료로 씁니다.

# 공유와 보관

## 공유 전 확인

- 참석자에게 초안을 먼저 보내 사실관계를 확인받습니다. 특히 결정 사항과 담당은 당사자 확인이 필요합니다.
- 외부 기관 참석 회의는 상대 기관에도 같은 회의록을 보내 합의 내용을 맞춥니다.
- 의결 기구 회의록은 규정에 따른 서명이나 승인 절차를 거칩니다.

## 녹음 파일과 녹취록 보관

회의록이 확정되면 녹음 파일과 녹취록의 보관 여부와 기간은 학교 기록물 관리 기준을 따릅니다. 기준이 없다면 회의 시작 때 알린 보관 기간이 지나면 삭제합니다. 음성 기록 도구의 클라우드에 남은 파일도 함께 지웁니다.

!!! 회의록을 공유하기 전에 확인합니다
- 녹음 동의를 받았고 민감 안건은 기록하지 않았다
- 녹취록의 참석자 이름을 역할로 바꾼 뒤 AI에 입력했다
- 결정 사항마다 녹취록에서 합의 발언을 확인했다
- 실행 과제마다 담당과 기한이 있거나 [미정]으로 표시되었다
- 날짜와 요일을 달력으로 확인했다
- 참석자에게 초안을 보내 사실관계를 확인받았다
- 녹음 파일 보관 기간을 정했다

# 바이탈에서 이어서 하기

- **보도자료·공지·회의록·결과보고서 작성 앱(회의록 모드):** 회의 메모를 붙여 넣으면 결정 문장과 할 일 문장을 구분하고, 문장 안의 담당("OO팀", "OO 교수")과 기한("1월 말", "11월 20일까지")을 찾아 표로 정리합니다. AI 없이 브라우저 안에서 동작하므로 내부 회의 메모도 외부로 보내지 않고 정리할 수 있습니다.
- **프롬프트 라이브러리 3-3:** 회의 녹취에서 회의록과 실행과제를 만드는 프롬프트를 입력칸 방식으로 씁니다.
